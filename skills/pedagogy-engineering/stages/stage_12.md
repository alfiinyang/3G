# Stage 12: Feedback Requirements

Specify how feedback conveys instructional insight, reinforces mental models, and guides corrective action.

---

## 1. Beyond Binary Feedback

> [!CAUTION]
> **Strict Prohibition**:
> Feedback must **never** be reduced merely to "Correct" or "Incorrect" (or generic "+10 Points" / "-1 Heart"). Feedback must expose the underlying domain causality, diagnostic reason, or corrective path.

---

## 2. Six Essential Feedback Modalities

Specify which activities trigger each feedback modality:

1. **Correctness Feedback (Verification)**: Immediate indication of whether the output or state is valid.
2. **Explanatory Feedback (Elaboration)**: Explains *why* an answer is correct or incorrect, referencing the underlying domain principle or mental model.
3. **Consequence Feedback (Domain Simulation)**: Exposes the authentic cause-and-effect reaction within the simulation or scenario (e.g. system overheats, balance sheet unbalances).
4. **Corrective Guidance**: Actionable instruction on how to remediate the specific flaw without just giving away the solution.
5. **Strategic Feedback**: Evaluates the efficiency, elegance, or method selection (e.g., "Your solution worked, but consumed 4x more memory than necessary").
6. **Progress Feedback**: Informs the learner where they stand relative to mastery of the objective.

---

## 3. Required Output Format

```markdown
### 12. Feedback Requirements

| Activity / Action | Feedback Modality | Trigger Condition | Information Conveyed & Corrective Value |
| :--- | :--- | :--- | :--- |
| **ACT-01** | Explanatory & Consequence | Incorrect parameter choice | Demonstrates system overload and explains Ohm's law ratio |
| **ACT-02** | Corrective Guidance | Logic error in loop | Highlights boundary condition and prompts check on termination |
| **ACT-03** | Strategic Feedback | Inefficient algorithm | Compares execution steps against optimal baseline |
```
