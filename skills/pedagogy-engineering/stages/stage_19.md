# Stage 19: Game-Form Requirements & Handoff Preparation

Derive the required game form from pedagogical interaction requirements and establish firm boundaries for handoff to the game designer.

---

## 1. The Game-Form Derivation Rule

> [!CAUTION]
> **Strict Anti-Genre Rule**:
> Genre or game form must **never** be the starting point. Never pick a genre simply because the topic is science, history, or programming.

Enforce this derivation chain at all times:

$$\mathbf{Goal} \longrightarrow \mathbf{Objectives} \longrightarrow \mathbf{Target\ Performance} \longrightarrow \mathbf{Activities} \longrightarrow \mathbf{Interactions} \longrightarrow \mathbf{Game\ Form}$$

---

## 2. Interaction Models to Game Forms

1. **Map Core Interaction Models**:
   - *Direct Manipulation / Sandbox*: Interacting with dynamic systemic variables (e.g. physics engine, circuit canvas).
   - *Diagnostic / Investigative*: Probing symptoms, interrogating logs, testing hypotheses.
   - *Strategic / Resource Management*: Allocating constrained assets under trade-offs.
   - *Puzzle / Construction*: Assembling components according to formal rules and constraints.
   - *Scenario / Branching Decision*: Navigating high-stakes decision trees with consequence feedback.

2. **Evaluate Candidate Game Forms**:
   - Evaluate candidate genres (Puzzle, Simulation, Adventure/Investigation, Strategy/Tycoon, Scenario-based, Sandbox/Builder, Hybrid).
   - Select or recommend the game form whose fundamental verbs directly match the learner activities and environmental requirements.

---

## 3. Game Designer Handoff Boundaries

Establish strict jurisdictional boundaries between pedagogy and game design:

### What the Pedagogy MUST Dictate to the Game Designer:
* What must be learned, why, and who the learners are;
* Exact capabilities learners must demonstrate;
* Content boundaries (core vs. excluded);
* Cognitive depth and progression sequencing;
* Support, scaffolding, and fading requirements;
* Diagnostic feedback and consequence requirements;
* **Learner-experience requirements** (agency, uncertainty, challenge pacing from Stage 16);
* **Learning-environment requirements** (manipulable elements, contextual fidelity from Stage 17);
* Valid evidence of learning and assessment rubrics;
* Required interaction verbs and recommended game form.

### What the Pedagogy MUST NOT Prescribe (Designer's Territory):
* Full game concept, themes, or story lore;
* Narrative characters, dialogue scripts, and cutscenes;
* Art style, visual assets, animations, or audio design;
* Specific UI layouts, menus, HUD styling, or button placement;
* Engine selection, code architecture, or technical implementation;
* Precise minute-by-minute level design or balance curves.

---

## 4. Required Output Format

```markdown
### 19. Game-Form Requirements & Handoff
- **Core Interaction Model**: [e.g., Diagnostic & Simulation-driven sandbox]
- **Candidate Game Forms Evaluated**: [Evaluated forms with brief trade-offs]
- **Recommended Game Form**: [Primary recommendation with detailed pedagogical justification]
- **Key Game-Form Characteristics**: [Essential mechanical affordances required]
- **Non-Negotiable Pedagogical Mandates**: [Absolute red lines the game design must satisfy, including experience & environment]
- **Flexible Creative Zones for Designer**: [Story, art, characters, audio, exact UI delegated to designer]
- **Open Questions for Game Designer**: [Key trade-offs or design challenges explicitly delegated]
```
